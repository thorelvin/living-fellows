Report and diagnosis
The user confirmed that money was taken from a Valuables shelf and returned
to that same storage. Code inspection found different field-collection and
personal-loadout targets: field scavenging admits three valuables, while the
personal loadout keeps none. Camp surplus handling then shelves them again.
The same mismatch can affect other non-loadout stock, extra crafting supplies
and temporary need bonuses. This diagnosis is from code and regression tests;
the local console was stale, not a current reproduction of the tester's loop.

Changes
- Ordinary scavenging of marked camp storage stops at the personal target.
  Needed personal supplies, real clothing/bag upgrades, unusable-weapon
  replacement and explicit supply requests keep their checked paths.
- Currency remains classified as Valuables without requiring a deposit marker.
  Different markers resolving to one physical container cannot create a trip.
- Shelf and floor sorting haul up to twenty compatible items per trip, limited
  by real inventory/carrying capacity. Same full type, live condition and name;
  every item remains a separate native identity with its original properties.
  Floor grouping stays on one source tile and one destination. Trash disposal
  and Log Yard bundling retain their existing special handling.
- One pickup/deposit pose per stack; each physical move is individually checked.
  Source reserves, destination permissions, protected items and competing work
  claims remain effective. Missing storage or unknown cargo blocks recovery.
- Optional job-target receipts preserve all native IDs across reloads. Partial
  deliveries preserve completed moves; cancellation returns remaining cargo.
  Confirmed death/removal releases affinity without changing corpse contents;
  dormant/unloaded workers retain receipts. No item reconstruction is added.
- Money/cash are mass nouns: "some money", while bundles/bars keep articles.

Performance and native inspection
No event handler, background service, native bridge or save-schema change.
Source discovery reuses the rotating eighty-item storage slice. Extra floor
pickup inspects at most forty-eight world objects. Recovery retains a cursor
and scans at most 256 items per work tick; groups contain at most twenty IDs.
Native getCountType is used only for qualified exact types, with the existing
fallback for other queries, avoiding repeated Lua scans for stack reserves.
Inspected installed ISInventoryTransferAction.lua and InventoryItem/
ItemContainer bytecode. InventoryItem.CanStack is a constant-false stub in
42.21.0, so it is deliberately not used to identify hauling groups. Vanilla's
transfer queue groups up to twenty items of one full type. Our native-shaped
test items deliberately return false from CanStack.
