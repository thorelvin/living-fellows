Compatibility changes
  PZArrayList was removed. The bridge now uses the actual List return type for
  tile objects and ArrayList for combat hit lists. The API check rejects an
  older compiled bridge still referencing PZArrayList; that rejection was
  reproduced against the previous shipping JAR before rebuilding.

  Sheet-rope actions now call climb/climbDown after the existing native rope
  validation. ClimbState and ClimbDownState retain traversal ownership.
  Automatic ladder routing and new crowbar jobs are outside this port.

  Runtime gates, both mod.info files, installer, Lua identity and documentation
  target 42.22.2. Save schemas and gameplay defaults are unchanged.

  The reproducible shipping bridge still uses JDK 17 and class-file major 61.
  Real-game tests need a separate JDK 25 compiler for the game's major-69
  classes. Both native test execution and Lua compilation use the bundled
  game JRE. Neither the JRE nor projectzomboid.jar was modified.

Log investigation after the first saved-world session
  The 17:54 session loaded the intended local 0.27.5 build and had no Lua/Java
  gameplay exceptions. Map loading logged 513 unmatched room IDs and 14
  unmatched building IDs. The native reader consumes these entries and skips
  their flags when no definition matches; it does not repair room geometry.
  The room flags are explored/lights/spawn/roof state, and building records
  include alarms, key IDs, visits and loot respawn state.

  A read-only parse of the subsequent normal save found 91,681 room records
  and 9,976 building records with the expected version-251 structure. All 14
  flagged building IDs and 509 flagged room IDs were absent from this new
  metadata. Those 523 specific stale entries should therefore not repeat
  without another map change; a later full load has not been tested.

  The four remaining room IDs (231, 327914, 327911, 655594 in cell 25,33) also
  occur in the local 42.21 session of 2026-11-08. They match an older report
  with no mods enabled and the same vanilla basement collision:
  https://theindiestone.com/forums/topic/98551-maniqui-and-basements-error/
  This is evidence against an LF regression; it is not an official diagnosis
  of this particular save. No save files or map definitions were modified.

  The LF startup warning was an eager client require of ISBuildingObject,
  which is supplied by the game's server-side world scripts. Removed that
  eager require; the placement callback already resolves the global at use
  time and rejects an unavailable tool safely. The existing context-menu
  suite passed all 1,739 assertions with actual stock ISBuildingObject loaded
  AFTER SCUIContext, including native one-click area completion and cleanup.
  This source follow-up is not installed; the player's game was not restarted.
