Living Fellows — companion stamina and moodle feedback isolation
2026-11-01; working changes on living_fellows/0.26.88
Runtime: installed Project Zomboid 42.21.0, single player.

Report and cause
The tester clarified that the real player's out-of-breath moodle shakes when a
companion hits a zombie. This is reproducible with Living Fellows alone.

CombatManager.attackCollisionCheck reads the attacking actor's own endurance,
tiredness, pain, panic and stress penalties, but its explicit wiggle calls use
the global MoodlesUI singleton. In solo view, an exhausted NPC therefore shakes
the real player's HUD. Native stamina deductions already use the explicit actor.

Change
Scope the moodle singleton only around the companion's synchronous native
collision check. Select a HUD only when its bound character is that exact actor;
otherwise select a cached, unregistered HUD which is never updated or rendered.
Restore the exact previous singleton after normal completion, nested callbacks
and exceptions. Keep native damage, penalties and stamina costs intact.

The scope leaves Stats, player lists, player counts, camera ownership and
UIManager's HUD array untouched. The offscreen HUD cache is renewed when the
primary player changes and does not retain that player strongly. No background
service or save migration is added.
