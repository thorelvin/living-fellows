# Build 42.21.0 native bridge port

The installed game updated from 42.20.4 to 42.21.0 on 2026-09-28. The mod's exact version gate displayed red because the 0.26.1 payload and native launcher were pinned to the old game JAR. Release 0.26.2 targets the new JAR and uses bridge protocol `42.21-isocompanion-13`.

| Runtime | JAR bytes | SHA-256 |
| --- | ---: | --- |
| 42.20.4 | 64,514,905 | `80E405A4BFC42F6072E75B3735F458A6514143DA011D3226007DED305A442F44` |
| 42.21.0 | 65,682,033 | `E1A69EB743EDE60B213A0FE7F8B83D4FCAB773036D256CC4543A336F3B058A33` |

The 42.21 JAR changed these bridge-facing contracts:

- `IsoGridSquare.getSpecialObjects()` now returns `List<IsoObject>` instead of `ArrayList<IsoObject>`. The bridge and compile stub now use `List`; the real-JAR signature gate checks the descriptor.
- `IsoGridSquare.getDoor`, `getWindow`, `getThumpableWindow`, and `getWindowFrame` now select `GridSquareEdge.NORTH` or `WEST` instead of a boolean. The bridge keeps its existing owning-square edge calculation and passes the enum to each lookup.
- `Event.callbacks` is now typed as `ArrayList<LuaClosure>`. The constructor callback guard uses the typed list.
- `GlobalModData.save()` now declares `IOException`. Both global-save call sites in the handoff and world-exit paths catch it and report a failed save.

The full source gate compiles the reproducible Java 17 bridge from stubs and checks the exact installed JAR hash. We also compiled all eight production Java sources directly against the 42.21.0 JAR with `javac --release 17`. A bytecode audit found no game method or field references present only in the stub build across its 18 compiled bridge classes. The core suite passed 47/47 harnesses against the real JAR, and `scripts/Test-Project.ps1 -Jobs 4` passed all nine stages, including gameplay, UI, installer, Workshop, and standalone packaging.

A cloned-save live client run (`SC-Harness-20260928-155933-e2557f83`) passed 23/23 checks. The installed bridge became ready, an existing saved companion occupied local slot 1 with 21 saved worn items, the player stayed in slot 0, the other three companions stayed registered, and the native companion remained active for the observation window. The screenshot is retained in `build/42.21-leader-smoke.png`. This smoke test did not exercise a door or window edge, so the new enum mapping is verified by the real-JAR signature and bytecode checks rather than a live doorway traversal. The expedition departure and distant-return limitations recorded in the playtest queue remain open.
