Living Fellows: stamina recovery and complete camp meals
2026-11-03; working changes on living_fellows/0.26.92, based on 7fb17f11.
Target: installed Project Zomboid 42.21.0, single-player.

Stamina diagnosis and change
The companion invokes the generic character update instead of IsoPlayer's local
input controller. Inspection of the installed IsoPlayer bytecode confirms that
updateInternal2 owns normal updateEndurance calls; separate sitting/resting and
vehicle paths already run. This accounts for recovery working only when seated.

The native actor now calls its own cached updateEndurance handle once after the
generic character update. It mirrors vanilla's remote-player currentSpeed values
from its existing movement flags. Standing recovery, eligible walking recovery,
running/sprinting costs, fitness, fatigue and heavy-load restrictions therefore
use the engine's existing calculations. Sitting, resting and vehicles retain
their existing native paths. Dead/god-mode actors, the singleton, disabled
character stats and unsupported multiplayer are excluded. Posture ownership is captured before the generic pass
so exiting a car, standing up or waking cannot add a second recovery that frame.
No stamina refund, shared Stats pointer, player-slot
change or global update wrapper is added. The cached call adds no world scan.

Sleep follow-up (November 3)
WakeState also gates updateStats_Sleeping to the singleton. The earlier fix
left sleep excluded under the incorrect assumption it already recovered.
Companions now run only that native method's endurance calculation while asleep:
the installed recovery constant, sandbox multiplier, own recovery modifier,
frame multiplier and the native all-players-asleep day-length factor. The normal
on-foot update stays excluded. Existing Downtime fatigue recovery continues to
own tiredness; hunger/thirst are not advanced again. Snapshotting sleep before
the generic pass prevents two recovery paths on entry/exit frames.

Meal diagnosis and change
The eating action already requests enough food to reach roughly 25% hunger, but
small foods cannot supply that much. After one item, the 75% admission threshold
could turn hunger work off before a complete meal. A companion on base duty now
keeps its meal episode active until actual hunger falls below 30%. Exactly 30%
still requests the final portion. Each portion uses a real native food action;
no scripted reduction of hunger or health is added. The starting threshold is
now 70% as requested, including narration and fallback defaults. Food preferences,
permissions, shortages, danger checks and travel
pause rules remain. Changing orders, leaving camp or joining an expedition ends
the duty-only episode. This runtime state adds no save schema or service.
