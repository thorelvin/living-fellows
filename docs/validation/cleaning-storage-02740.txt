Living Fellows 0.27.40 - cleaning tools and camp storage
Baseline: 3018febe (0.27.39). Windows PowerShell 5.1, pinned PZ 42.22.2.

Reported behavior
-----------------
Mops were stored among weapons/ammunition; a cleaner reported missing tools;
companions did not deposit sorted stock into General source.

Confirmed defect
----------------
The installed game's weapon.txt defines Base.Mop and Base.Broom as HandWeapon
items, category Weapon, display category HouseholdWeapon, with the native
base:cleanstains tag. LF's two classifiers did not recognize that cleaning role,
so both fell through to their generic weapon category. The screenshot's red
marker reads Weapons; either Weapons or Ammunition can be corrected by sorting.

CleaningSupplies.isTool now recognizes the native tag independently of condition.
The existing tool() predicate still rejects broken items. Camp classification
checks the cleaning role before the weapon fallback; logistics checks it after
trash detection and before weapon loadout/cargo rules. HouseholdWeapon alone is
not sufficient: unrelated household weapons retain their existing category.
No item definitions or native zombie navigation are changed.

Native verification also exposed a completion-boundary defect. finishWork
starts the normal post-action pause inside the BaseWork update, after Decision
has already admitted the work. Returning a loan in that same call could issue
movement which NativeActions rejected as action_pacing:clean_base. The path
controller recorded that as a navigation failure. returnCleaningLoans now waits
before each ordinary carried-loan return; it keeps the live job, exact items and
markers, then resumes after the original pause. Direct cancellation rollback
does not wait. The guard neither shortens pacing nor alters navigation.

The cleaning planner already searches every withdrawable marked storage, not
only Tools. Discovery permissions, reserves, item ownership, loans and the
three-minute missing-supply retry are unchanged. The supplied screenshot does
not reveal item condition or reservations, so it does not establish a separate
missing-tool search defect.
The new repayment defect can interfere with tool availability, but the supplied
evidence does not prove that it caused the tester's particular warning.

General source is a staging/input shelf. Ordinary sorting deliberately empties
it into the dedicated categories; it is not a fallback sorting destination.
Camp storage help now explains that behavior and identifies Tools as the home
for cleaning tools and cleaner. Car unloading's existing staging fallback is
unchanged.
