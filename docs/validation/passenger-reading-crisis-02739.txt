Passenger reading
-----------------
The reported passenger could select Read, but vehicle-carried world movement
tripped the supervisor's 0.25-metre protected-pose invariant. A production
controller reproducer failed with protected_pose_moved; its stationary control
passed. The later support report records the same invariant for the companion.

Reading now opts into an exact vehicle-and-seat reference. Vehicle motion is
allowed only while that passenger attachment remains verifiable. Exiting,
changing seats or vehicles, taking the wheel or losing seat verification
interrupts the chapter. Other work and on-foot reading keep their world-position
guard. Danger, new orders, native action verification and watchdogs still apply.

Production Kahlua regressions: 42 passenger checks pass, alongside the existing
reading-session cases. They cover moving completion, one page reward, exact book
ownership, exit/seat/vehicle/driver changes, an unreadable native seat, ordinary
on-foot movement, unrelated work, danger, new orders and a stalled-action bound.

Real native PZO comparison: with only the reading opt-in removed from the
disposable payload, the actual car travels 0.267 metres before reading is
cancelled with protected_pose_moved. The native assertion exits 1.
  Evidence: build/pzo-passenger-20261118-224048-4875d3.

The final positive uses native seats and physics, a companion driver and reader,
and the primary player in another passenger seat. A 220-page Carpentry volume
must grant one 11-page chapter, preserve the marked book, and grant no extra
pages when the next chapter is interrupted by a native vehicle exit. The probe
honors stock native timing, the existing supervisor watchdog and the ordinary
60-second repeat cooldown; it then checks a 60-second post-interruption soak.
  Final native outcome: exit 0. Travel 8.028 metres; selected duration 117420 ms,

  exit interrupts the next chapter, no additional pages appear during the final
  60-second soak, and maximum observed tick gap is 95 ms.

Crisis controls
---------------
Choosing the same verdict increments the crisis decision revision. The cached
Base page omitted that revision, leaving later buttons bound to an obsolete
snapshot. The production UI refresh regression reproduces the missed rebuild.

The structural signature now includes the revision, stage, pending explanation
and action gates, with sufficient bounded space for them. An already-active
Watch policy is explicitly labeled current and disabled; alternative decisions
and End crisis and return to normal duty remain available. An active Watch
policy still permits indoor duties; releasing it is the separate normal-duty
action. Existing final-outcome confirmation and revision checks remain intact.

Production callback tests cover selected Watch, an alternative, exact crisis and
revision dispatch, normal-duty release and concurrent-change rejection feedback.
Refresh tests cover revision-only changes and each newly tracked structural gate.

show that bridge loaded and the original companion active again.

The reported 0.27.37 freeze still has no identified cause. The tester later
confirmed complete unresponsiveness with 0% reported CPU usage. That is consistent
with waiting/blocked threads; it does not identify a particular lock or component.
The console stops at
17:42:01 without a clean exit; PZO diagnoses an unclean session, not a specific
crash. No JVM fatal-error log or frozen-process thread dump was supplied. The

These fixes must not be described as a proven fix for that unexplained freeze.
