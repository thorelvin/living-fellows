Problem and patch
-----------------
The reported 0.27.35 log loads the Lua mod with SCBridge absent and actors disabled.
The recruited companion's restore then enters quarantine for that same reason.
The subsequently supplied PZO logs confirm the startup cause. On 2026-11-17,
PZO approved and initialized the 0.27.34 bridge (hash 16463719ec55e184c02fdabb34bda144d75538cf73356717be05a34b26b26236).
On 2026-11-18 at 12:45:12, it skipped the 0.27.35 bridge (hash
fc6342519ec0b95d13af2b19dfdb0548357f6208fb107ba0b9cdcd5cb51eb22d)
for that launch, reporting zero loaded and zero errors. The supplied PZO config
has Java loading enabled, the old hash approved and no blocked hashes; the new
hash is not approved. The logs do not identify how the approval prompt ended.

The missing-bootstrap error was omitted from transient restore failures. It
therefore spent the companion's six-attempt budget and stopped probing.
The patch classifies only this explicit missing-global error as environmental.
Incompatible bridge, readiness and inventory failures keep their bounded policy.
Pending raw records remain unchanged in synchronous and scheduled saves.

When PZOEngine is present and SCBridge is absent, LF now explains the PZO Java
setting and per-update approval step. Installer output and setup instructions
explain the same requirement. PZO settings and approval choices are not changed.
