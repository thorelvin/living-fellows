# 0.20.0 — Faction World and Living Base

## Faction World

Persistent households now form a bounded pairwise world graph. Relations begin
deterministically, use the states Hostile, Tense, Neutral, Cooperative and
Allied, and change through slow world events: cautious contact, shared warnings,
supply exchange, medical aid and boundary disputes. Recent known events appear
in the Factions tab. Debug builds can force every event without waiting.

Meaningful standing changes and fair trade can travel to another household only
when the player knows both groups. The reaction is small, relation-weighted and
recursion-guarded. Unknown groups do not leak through the UI. World simulation
never applies damage, death, destruction or inventory transfer off-screen.

The graph and its bounded news log are part of save schema 2. Missing state is
created additively; orphaned edges are removed when a group no longer exists;
lower sandbox population limits never prune an existing household.

## Living Base

The Base tab now audits loaded, explicitly classified storage against targets
scaled to the resident roster. Food, water, medicine, construction supplies and
guard ammunition are reported separately. Unloaded storage is identified as
unknown rather than silently counted as empty. Role coverage, zone gaps and a
single readiness score make the next useful camp improvement visible.

Base policy is persistent:

- Defense: rotating watch, all assigned guards, or all available residents.
- Workload: essential, balanced, or continuous.
- Safe routines: allow or suppress ambient reading, seating, washing and useful
  carried-item work while on base duty.
- Automatic maintenance: allow or suppress sorting and registered maintenance.

The rotating watch is deterministic and does not create a second scheduler.
Immediate danger still preempts every job and every policy. A resident with no
job uses safe downtime rather than spinning on `no_base_job`. Automatic sorting,
repair and supply-crafting jobs are created only after a loaded on-duty resident
and an actionable real item are found.

## Verification

The Kahlua gameplay harness covers relation creation, consequence propagation,
world events, save/restore, orphan cleanup, stock audits, policy persistence and
guard selection. Static checks enforce bounded state and transactional
persistence. The full project gate also compiles every Lua module, validates the
native bridge, runs the UI suite and rebuilds the Workshop archive.
