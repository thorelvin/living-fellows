PZO launcher coexistence — release 0.27.2 — 7 November 2026

Cause and implementation

The reported mainClass com/pzoptimizer/PZOEntrypoint belongs to prop11's PZO,
not xD3I's PZ Optimization covered by the existing combat adapter. LF's former
installer accepted only vanilla main or its own wrapper. Merely allowing PZO
would bypass PZO initialization, and delegating from LF would last only until
PZO's configuration migrator restored its own mainClass.

The installer now recognizes PZO with its entry class on the actual classpath,
preserves its main and VM options, and adds -javaagent:LivingFellowsBridge.jar.
The new Premain-Class invokes the same idempotent, nontransforming LF bootstrap.
It adds no bytecode transformer. The existing worker arms its exposure timeout
after the game thread starts, allowing host setup dialogs before game startup.
Vanilla installations retain the existing SCLauncher route. Unknown launchers
and ambiguous ownership still stop before mutation.

Ownership schema 4 records agent mode; older wrapper records remain supported.
Switching an existing LF wrapper installation to PZO adopts the current PZO
configuration, minus LF-owned entries, as the uninstall baseline. Exact and
selective uninstall preserve PZO and foreign configuration. Dotted/slashed
PZO class names compare equivalently. Rejected prepublish config races no
longer restore an obsolete snapshot over the foreign edit.

The matching rebuilt LF bridge is shipped with Lua. No PZO code, engine JAR
or native DLL is included in the release. Protocol remains 42.21-isocompanion-30;
behavior was tested as a 0.27.1 candidate; final release metadata is 0.27.2
and save schemas are unchanged.

Warning review against earlier evidence

The stale lifetime-receipt fields also occur in an earlier non-PZO combat run
(SC-Harness-20261106-180219-4e32ca12), so they are an existing measurement flaw.
The eleven inventory-ID errors were absent from the earlier logs inspected;
their caller and affected item identities are not recorded. Inventory
compatibility is therefore not certified by this short combat run. The three
VehiclesDB2 WAL-transaction notices come from PZO's SaveGameStreamBooster and
did not abort the run. Font, icon, map and vanilla require warnings also occur
in the non-PZO seed baseline.
