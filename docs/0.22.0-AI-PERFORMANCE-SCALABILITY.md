# Living Fellows 0.22.0 — AI performance and scalability

## Goal

Living Fellows must remain responsive with one to sixteen active companions. Expensive AI work is measured, globally bounded and resumable. Combat and survival reactions keep their cadence while routine work degrades gracefully during sustained load.

## Runtime contract

- The scheduler owns a 2 ms target budget per game frame.
- Tasks run in `critical`, `high`, `normal` or `background` lanes. Due critical work always precedes lower lanes.
- Load level 0–3 is derived from a rolling frame-time window. Critical cadence is unchanged. Normal and background intervals increase as sustained overload rises.
- Perception, pathfinding, scavenging discovery/scoring and production faction-house discovery preserve a job frontier and continue in later frames.
- Global unit quotas are shared by every active companion in a frame. Runtime round-robin selection prevents actor starvation.
- Immediate navigation may use the urgent reserve. Ordinary perception and work never consume that survival reserve.

## Resumable systems

### Perception

A scan job owns its origin, rotating outer-band phase, offset list, discovered threats and next offset. Each production call consumes only the granted square quota. Nearby results remain available while the outer scan completes. A 75 ms coordinate cache shares raw moving-object reads between close companions without retaining stale world data for a full AI interval.

### Navigation

The A* frontier, open/closed sets, costs and parents persist in a route job. Primary and alternative routes resume independently. Follow-route evaluation still considers traversal cost, threat exposure, crowding and turns after all bounded candidates complete. Material goal, stance or blocker changes discard the obsolete job; small leader movement does not restart it.

### Scavenging

Container discovery retains its sampled offsets and candidates. Candidate scoring advances by a bounded number of containers per frame. The best container remains exclusively reserved between slices, and command/danger/reset cancellation releases both the reservation and unfinished search state. The existing animation-before-commit and verified transfer transaction remains unchanged.

### Faction houses

Production household discovery retains its candidate sample cursor across faction pulses. The daily roll occurs once, and a pending search can finish without repeating that roll. Debug spawning remains synchronous because it is an explicit one-shot test command.

## Profiler

`SCPerformance` records rolling per-system and per-companion samples:

- runs, total, last, average, p50, p95 and maximum milliseconds;
- over-budget calls, yielded jobs and processed units;
- frame p50/p95/max, over-budget/deferred frames and adaptive load level;
- shared-cache hits and misses.

The debug-only tab shows the five most expensive systems and companions. Refresh is explicit so changing metrics cannot interrupt panel scrolling. The report can be copied to the clipboard or reset.

## Verification

Automated coverage exercises 1, 4, 8 and 16 simulated companions, shared quota ceilings, round-robin progress, critical-before-background ordering, adaptive load shedding, cache expiry, report export and critical cadence. Gameplay coverage proves that perception, navigation, scavenging and faction-house jobs yield and then reach a terminal result. The full project gate and protected live sandbox remain mandatory before release.
