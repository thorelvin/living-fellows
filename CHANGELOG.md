# Changelog

## 0.22.8 - Reliability playtest candidate

- Gave each companion decision a stable identity so "patch myself", "patch the player" and "patch a hurt ally" are no longer treated as the same choice (review 2.4). They previously all counted as the generic "medical" decision, so the state-stickiness that prevents flip-flopping -- and the fallback that tries a lesser option when the best one has no action -- could not tell them apart, and a companion that couldn't treat itself would not fall back to helping someone else. Each candidate now carries a distinct key (kind plus mode and target), so hysteresis and fallback act on the exact decision.
- Surfaced the native swing/floor-attack collision capability instead of failing it silently (review 4.3). The bridge could report ready while the combat-collision reflection was missing, which left a combat companion swinging without ever landing a hit and no way to tell why. The bridge now exposes explicit combat-collision and floor-attack (stomp) capability flags; the support/health view reports a degraded combat state and warns once when the collision path is unavailable, and a real-JAR test asserts both capabilities resolve on the shipped build. A missing floor attack degrades only the stomp, not general melee or ranged combat.
- Made incoming zombie attacks edge-triggered so each swing wounds a companion exactly once (review 4.7). A zombie's attack state -- and its "success" outcome afterwards -- stays true for many frames, so the previous per-frame check re-applied the same swing repeatedly, held off only by a fixed time cooldown that in turn swallowed a genuinely fast second swing. Each swing is now resolved once on its rising edge and held until the zombie leaves the attack, so a slow attacker can't double-wound and a fast attacker's second swing still lands.
- Fixed zombies walking up to a companion and then just standing there instead of attacking. The code that keeps a zombie's "recently seen target" clock fresh for a non-local companion (stock vision only refreshes it against the local player array) wrote the native field directly, which throws in Kahlua every frame and silently never applied — so the zombie kept lapsing out of its swing. It now drives the native `setTargetSeenTime` setter, so zombies commit to attacks (and bites) on companions again.
- Fixed a companion's menu roster entry breaking (and spamming the log every UI refresh) once it had accumulated enough relationship memories. The roster summary copied the companion's entire memories array, which is nested one level deeper than the summary's copy depth and grew past its value budget, so the bounded-copy guard threw "stable value limit exceeded" on every refresh at around thirteen memories -- leaving that companion's roster data unavailable. No summary reader used the array (the memory view reads the live memories directly), so the summary now carries just a bounded memory count.
- Fixed a teleport-recovered companion being permanently despawned ("body never shows up again"). When a follower that had unloaded was teleported back to the player, the runtime health gate re-checked native validity on the same tick and, if it had not yet settled, removed the companion outright with no retry. Native validity dips transiently for a few frames after a teleport re-seats the actor on a fresh square, so the health gate now tolerates a bounded settling window (default 1.5s) and only tears down a companion whose native state stays broken past it -- a genuinely dead actor is still retired immediately by the death path.
- Fixed companions freezing for minutes at a fence or wall after teleporting in to follow the player. A non-local companion teleported mid-climb never finishes the climb animation, so it stayed in a native "climbing" state that navigation could only wait on -- looping forever without moving. A climb that outlives its timeout now cancels the stale movement owner, temporarily blacklists the unfinished climb edge, and reroutes around the obstacle instead of standing frozen (the same active recovery that already handled stuck wall-collision states).
- Fixed companions freezing permanently in a "kneel treat"/"rip clothing" pose after a medical action was interrupted (reported as "Urgent already queued, just stands still locked up" and companions stuck at treat-wound). An interrupted native visual action left a dead record that kept reporting as a live activity, so the urgent-decision path re-queued forever and the supervisor's urgent dispatch stayed blocked, while the interrupted kneel pose was never reset. A stopped/interrupted visual is now self-healed the moment its status is read: it is cleared (which also resets the model pose) and reported as idle, so the companion re-decides and moves instead of locking up.
- Added one actor-wide supervisor for movement and timed actions, with explicit ownership, completion, cancellation, retry, rollback, and support evidence.
- Fixed drawn melee weapons failing to swing: the bridge now exposes and verifies Build 42.20.4's native `AttackType`, the action adapter performs the real player attack preflight/authorization, and melee followers safely close the final gap instead of kiting forever.
- Fixed companion (and hostile-faction NPC) melee swings connecting but dealing no damage: Build 42's swing-collision anim event only resolves a hit for the local player, so a non-local actor animated and found targets but never applied damage. The native actor now drives the collision check itself on that event, using the `AttackType` the swing animation carries so the hit passes the engine's stance filter and lands.
- Companions now clear a jammed firearm by racking it (the same action the player's firearm menu uses) before firing or reloading, instead of standing on a dead gun. Verified end to end alongside firing, magazine reloads, and reusing a reloaded weapon.
- Restricted the "catch up to the player" chunk-unload recovery to following companions. A companion set to stay, guard, or base duty is no longer teleported across the map when the player walks out of range; its record is kept intact so it reloads at its post when the player returns.
- Fixed a teleport-recovered companion appearing to vanish: it still showed on the minimap, could be looted, and drew zombies to its tile, but stood invisible and never moved. The recovery restored the actor's square and render model but never returned it to the cell object list the update scheduler iterates, so it was never ticked (which also let its render alpha fade out). Recovery now reschedules the actor, so it moves and stays visible immediately after a teleport.
- Fixed zombies ignoring companions — following them but never biting. Build 42's zombie vision only scans the local `players[]` array, so a detached companion is never "seen": its target-lock decayed every frame (the zombie just walked toward it) and, even when a swing resolved, the bite is written by the victim's local-player-gated processing that never runs for a non-local actor. Companions now refresh the same seen-flesh timer continuous vision keeps (holding the lock without altering zombie AI) and take real BodyDamage wounds from a landed attack — bites can infect and turn them, while scratches and lacerations wound and bleed without infecting.
- Streamlined the companion panel from nine tabs to five (Status, Orders, Loadout, Base, More): merged the Gear and Health tabs into one Loadout page, moved Groups/Factions/Journal/Support behind a "More" launcher, dropped status readouts that duplicated other tabs, and collapsed the two overlapping combat controls (a per-companion stance selector plus a separate team doctrine selector) into a single per-companion combat selector with an "Apply to whole squad" button. The doctrine still cascades to the underlying stance and hold-fire, so behavior and saves are unchanged.
- Added zombie pull-downs: when enough zombies pile onto a companion at once, they can grab and drag it to the ground (resisted by the companion's traits), pinning it while it is torn at. A pinned companion cannot act and cries out for help; there is a grace window to save it — thin the swarm and it is freed, bloodied but alive; leave it and the pack drags it down for good.
- Companions now finish a downed zombie with a head stomp: they step onto the zombie's head square (`getHeadSquare`) and stomp the skull — the lethal spot — for a clean kill, while a stomp landed anywhere else only wounds and keeps it pinned. The finisher's damage is applied once, only after the native swing has actually started, so a rejected or retried stomp never harms the target, and it is the sole damage owner (Build 42's floor attack never resolves a downed target for a non-local actor).
- Hardened the companion↔local-player boundary and grab handling after an external code review: the engine's standalone `postupdate()` pass now runs inside the same local-player snapshot/restore as `update()` (an unguarded post-update pass could leak player-indexed ownership and disturb the real player's hotbar/inventory), while nested post-update calls stay under `update()`'s existing guard so the multi-frame swing animation is left intact; a companion that boards a vehicle or is removed/reset while grabbed now has its pin cleared so its decisions resume; and the zombie pull-down "pile" only counts zombies actually committed to that companion (tolerating brief target flicker) instead of every zombie in range, so a swarm attacking the player no longer drags a bystanding companion down.
- Companion timed actions (work/reload/etc.) are cancelled by removing only the Living-Fellows-owned action instance instead of clearing the whole native timed-action queue, so an unrelated mod's action queued on the companion is never dropped.
- Made the global `ISInventoryPage` container hooks argument- and return-safe: the `selectContainer`/`setNewContainer` wrappers now forward every argument and preserve every return value (including multiple returns), so a Build update or another inventory/hotbar mod that adds parameters or returns extra values is no longer silently corrupted.
- Companions are no longer frozen in place by low health. Knox infection and injuries now just lower a companion's health and it keeps acting like a player — moving, fighting, fleeing, and being bandaged — until it dies at zero health or turns at terminal Knox, instead of being forced into an immobile "downed" state at low health (which also left it standing frozen rather than reacting). Any companion still stuck in a legacy downed state stands back up.
- Fixed companions and faction members reloading naked (their clothing left in inventory): Build 42's `setWornItem` takes an `ItemBodyLocation` object, but restore/equip/bandage code passed the persisted location string, so the native call found no matching overload and silently dropped every worn item. Those calls now resolve the location from the item's own `getBodyLocation()`, so saved clothing (and bandages) are actually re-worn on load.
- Companions no longer decide to reload on ammunition they cannot actually use: the reload check now matches a magazine of the weapon's exact magazine type (that still holds rounds) or loose rounds of its exact ammo type, instead of accepting any item whose name merely contains "ammo"/"bullets"/"shells" — which previously matched the wrong calibre or an empty magazine and produced repeated failed reload attempts.
- A companion that starts to swing but has the attack rejected during preflight (equip not ready, weapon not attack-ready, authorization unavailable, etc.) no longer stays unnaturally locked facing a stale target: every rejected attack now clears the precise aim target, floor-aim, and downed-target state through one structured cleanup path instead of leaving the native actor re-facing the old target every frame.
- Borrowing the player's loot pane to show a companion's inventory is now a reversible transaction: the pane's prior container, visibility and collapsed state are snapshotted and put back when the companion panel closes or minimizes or you leave the Loadout tab — but only while the pane still shows the companion container, so a container you deliberately opened afterwards is left alone.
- Fixed the intermittent companion vanish (and the "flaky" ranged/melee failures that were its downstream symptoms) at the root: the per-frame locomotion speed refresh (`updateMovementRates` → `calculateWalkSpeed` → `calculateSneakLimpSpeedScale`) reads a limp/sneak animation-variable slot that is momentarily null on the non-local companion **while it is limping from a leg wound**, throwing every frame, failing the whole native update, and tripping the health gate into a remove+respawn. That non-critical speed refresh is now guarded, so a limping companion keeps updating instead of disappearing. Verified with eight consecutive live-sandbox runs: zero removals, zero animation NPEs, ranged fully reliable (previously it failed roughly one run in four to six).
- Melee companions now swing from a distance keyed to their weapon's actual reach instead of a fixed gap: a short blade closes in to connect while a long blade holds a safer gap and still lands, and a companion backs off to reopen its swing range when a target crowds inside it — so it keeps kiting distance yet actually hits, instead of missing with short weapons or over-closing with long ones.
- Fixed on-foot ranged companions drawing and swinging a melee weapon: the ranged-support doctrine now selects the firearm whether or not the companion is seated, so an approaching zombie no longer flips the pick to melee when the saved weapon priority is stale.
- Fixed companions becoming invisible while still present (visible only on the minimap, "body never returns" after a teleport or chunk reload): the native actor now forces full render opacity each update, since the vanilla visibility fade never raised its alpha.
- Fixed companions being under-simulated and, when stationary, effectively frozen (idle animations, attacks that started but never landed, "just standing there doing nothing"): a manually constructed non-local actor was only placed in the cell's deferred add list, so Build 42's update scheduler stopped ticking it. The runtime now keeps every live companion in the cell object list each frame, so they are simulated like normal characters and melee swings resolve their hit.
- Fixed a companion vanishing mid-fight and returning as a fresh, unequipped body: a per-frame native diagnostic read an animation variable whose slot is momentarily null on the non-local actor, and the resulting exception failed the runtime health gate, which removed and respawned the companion. That read is now guarded, and a recoverable native-update exception is tolerated for a bounded window (the local player is always restored first) instead of tearing the companion down on the first hiccup.
- Made medical care, downtime, scavenging, logistics, vehicle seating, equipment, and loadout changes transactional instead of applying partial effects.
- Made in-combat self-bandaging low priority: a companion no longer stops to patch itself while a zombie is attacking it in melee range (or while pinned with no way out). It fights or repositions first and treats the wound only once at least semi-safe; a critical wound still drops it into the downed path.
- Hardened navigation recovery with bounded retries, temporary failed-edge blacklists, native blocker classification, and detailed recovery evidence.
- Made bootstrap hooks, runtime startup/reset, registry writes, return-tuple handling, and mutable record ownership transactional and idempotent.
- Replaced partial save copies with strict path-aware copies. Uncopyable envelopes block overwrite, while copyable invalid records and failed subsystem documents remain quarantined and recoverable without losing their untouched raw value.
- Added bounded restore backoff and manual retry for deterministic incompatibilities.
- Kept failed native cleanup actors reachable and retryable, and hard-gated every reflection-dependent Build 42.20.4 method before spawning.
- Fixed the standalone `Install.bat`/`Uninstall.bat` failing with "Illegal characters in the path" no matter where the zip was unpacked: `%~dp0` ends with a backslash, so passing a bare `"%~dp0"` made the trailing `\"` an escaped quote, and PowerShell swallowed the rest of the line into `-ProjectRoot`. The wrappers now strip the trailing backslash before handing the path to the installer, and a test guards the wrappers against reintroducing the pattern.
- Rebuilt local/native installation as one hash-verified transaction with rollback at every commit boundary and safe refusal of ambiguous legacy launcher state.
- Unified configuration views, provider identifiers, scheduler metrics, faction limits, Java/Lua list access, and checked transaction helpers.
- Bounded the dynamic perception cache with incremental expiry sweeping, and added source-only CI plus a trusted real-JAR compatibility workflow.

## 0.22.7 - Public playtest candidate

- Added capability-aware combat readiness using injuries, endurance, panic, pain, fatigue, stress, morale, carry load, skills, weapon quality, support, threat directions, footing, and escape quality.
- Improved target distribution, stamina preservation, side/rear threat priority, shove-and-ground decisions, melee spacing, kiting, and retreat selection.
- Added deliberate firearm sight-picture timing without delaying immediate defensive fire.
- Hardened movement ownership, choke-point reservations, native path telemetry, obstacle memory, stuck recovery, escape priority, and Copy player movement.
- Expanded varied, situational English dialogue and combat calls with safe cadence and real sound consequences.
- Added persistent households, faction relations, contracts, recruitment trials, living bases, grief, personality, and transactional save schema 2.
- Added the public standalone Windows package with reversible `Install.bat` and `Uninstall.bat` support. The installer never modifies `projectzomboid.jar` and verifies launcher rollback in an isolated build test.
- Retained Steam Workshop support through ZombieBuddy 2.3.3 or newer.

Earlier implementation history and subsystem-level changes remain documented in [SurvivorCompanion/README.txt](SurvivorCompanion/README.txt).
